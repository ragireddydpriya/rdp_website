CDC (Change Data Capture) Architecture

Key Innovation: Unified CDC tracking across all layers for optimal performance and context awareness.

  • CDC Control Table: Centralized version tracking for Bronze → Silver → Gold transitions.
  • Incremental Processing: Only changed data processed after initial full load, maintaining context for calculations.
  • Version Tracking: Each layer tracks last processed version from upstream tables.
  • First-Run Detection: Automatically handles initial full load vs. incremental updates.

Job Orchestration Flow

  1. Bronze Layer: Ingests S3 Parquet files (incremental & one-time loads), normalizes schema, performs basic cleaning, applies dynamic type conversions per workflow config, outputs unique workflow IDs, and moves processed files for audit.
  2. Silver Layer: Processes CDC changes from Bronze, maintains context for window functions, applies SCD2 logic, calculates business metrics, and merges into Silver Delta table with version tracking.
  3. Gold Layer: Consumes CDC changes from Silver, evolves schema per requirements, flattens queryable JSON output, and produces analytics-ready tables for BI/reporting.

Performance & Reliability

  • AQE Tuning: Adaptive Query Execution configured per layer based on data volume.
  • Batch Operations: Bulk file operations with fallback strategies to avoid lock contention.
  • Error Resilience: Comprehensive error handling with detailed logging and email notifications for failures.
  • Storage Management: Automated cleanup of processed files with configurable retention (7 days PROD, 3 days otherwise).

Configuration & Extensibility

  • All parameters configurable via YAML files (no code changes needed).
  • Schema evolution support — adding new fields and workflows requires no code rewrite.
  • Full audit trail via SCD2 tables and centralized logging for compliance and troubleshooting.
